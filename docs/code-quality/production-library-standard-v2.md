## Dimension 1: Architecture

Every format is a **standalone library** with exactly one consumer-facing namespace.

Layers (inner → outer):

```
Spec Layer      — spec/ stubs: architecture_only markers, spec_qname, no behavior
Domain Layer    — models.py: spec-derived data classes with from_file() factory
Parser Layer    — parser.py or codec.py: bytes → domain model, no analytics
Writer Layer    — writer.py or codec.py: domain model → bytes (if writable)
Analytics Layer — {format}_analytics.py: statistics/metrics/aggregates, no I/O
Export Layer    — {format}_to_{target}.py: cross-format conversions
Compat Layer    — Compat/{format}_{class}.py: facade classes (spec QName binding)
Public API      — __init__.py: re-exports only, declares explicit __all__
```

Rules:
- A file may occupy AT MOST ONE layer (single responsibility).
- No file may import from a higher layer (parser must not import analytics).
- No file in the Public API layer may contain business logic.

**Enforcing validators:** V66 (multi-responsibility), V69 (analytics naming), V35 (LOC cap).

## Dimension 2: Python Source Layout

```
src/python/{format}/
  __init__.py            # re-exports + explicit __all__, ≤100 LOC
  {format}_parser.py     # or parser.py — parse-only, ≤800 LOC
  {format}_writer.py     # or writer.py — write-only (if writable), ≤800 LOC
  models.py              # domain model classes with spec_qname, ≤200 LOC
  {format}_analytics.py  # statistics functions only, ≤800 LOC per file
  exceptions.py          # exception hierarchy, ≤100 LOC
  constants.py           # namespace URIs, magic bytes (if applicable), ≤200 LOC
  Compat/                # facade classes — one file per spec QName entry
  spec/                  # architecture_only stubs generated by generate_canonical_stubs.py
```

**Forbidden naming patterns:**
- `{format}_document.py` whose module docstring (first non-blank line) contains the substring
  `"analytics functions"` — this is the "analytics masquerade" anti-pattern (V69)
- `{format}_codec.py` exceeding 400 LOC when a `{format}_analytics.py` already exists
- `_analytics_extra.py`, `_misc.py`, `_helpers.py` (V50 already blocks these)
- Multiple analytics files without an `analytics/` sub-package

**Enforcing validators:** V35, V50, V65, V66, V69.

## Dimension 4: Domain Object Models (Python)

- Every domain class MUST carry `spec_qname: ClassVar[str]` matching the qname-registry entry.
  Use `ClassVar[str]` (not `str`) for dataclasses to avoid instance field creation.
- `from_file(path: Path | str)` class method is required.
- Domain classes hold NO I/O logic and NO analytics.
- `to_dict()` is acceptable; `to_csv()` or `to_xml()` belong in the Export Layer.
- `spec_qname` must match `shared/qname-registry/{format}.yaml` canonical entry.

**Reference implementations:** `src/python/ndjson/models.py`, `src/python/gnumeric/models.py`

**Enforcing validators:** V53 (spec_qname compliance), V66 (role separation).

---

## Dimension 5: Domain Object Models (.NET)

- `{Format}Document` is sealed (or final) with no static `Parse()` method.
- Parse logic lives in `{Format}Parser`.
- Every public property has an XML doc comment (`/// <summary>`).
- No public `static` utility classes; use extension methods or factory methods.

**Enforcing validators:** V70 (LOC cap).

---

## Dimension 6: Parser / Writer Separation

Python:
- Parser file contains ONLY parsing logic (bytes/str → domain model).
- Writer file contains ONLY serialization logic (domain model → bytes/str).
- A codec file (`{format}_codec.py`) is acceptable ONLY when it handles exactly 2 roles
  (load + write) with no analytics. If analytics exist in the same file: FAIL (V66).

.NET:
- `{Format}Parser.cs` — parse only.
- `{Format}Writer.cs` — write only.
- No format with separate analytics in `{Format}Analytics.cs` may have analytics logic
  inside `{Format}Parser.cs`.

**Enforcing validators:** V66 (blocks_sprint=True in v2).

---

## Dimension 7: Analytics Separation

Python:
- All statistics, aggregation, and metrics functions belong in `{format}_analytics.py`.
- The parser/codec file may import from analytics: `try: from .{format}_analytics import *; except ImportError: pass`
- Analytics files are NOT imported in `__init__.py` directly — they are re-exported via the codec/parser wildcard.
- Analytics file naming: `{format}_analytics.py` (singular). The `_document.py` suffix is
  reserved for domain models. A file named `{format}_document.py` that contains analytics
  is an **analytics masquerade** — blocked by V69 in v2.

**Known analytics masquerade files (to be healed in PROD-GOVERNANCE-001):**
- `src/python/gnumeric/workbook_document.py` → rename to `gnumeric_analytics.py` (TC-GP-PY-001)
- `src/python/toml/config_document.py` → rename to `toml_analytics.py` (TC-GP-PY-004)

**Enforcing validators:** V69 (blocks_sprint=True — NEW in v2).

## Dimension 8: Naming Conventions

| Concept | Python name | .NET name |
|---------|------------|-----------|
| Core codec | `{format}_codec.py` or `{format}_parser.py` | `{Format}Parser.cs` |
| Writer | `{format}_writer.py` or `writer.py` | `{Format}Writer.cs` |
| Statistics | `{format}_analytics.py` | `{Format}Analytics.cs` or `Model/{Format}Metrics.cs` |
| Domain model | `models.py` | `{Format}Document.cs` |
| Exceptions | `exceptions.py` | `Exceptions/{Format}Exception.cs` |
| Constants | `constants.py` | `{Format}Constants.cs` |

**Forbidden names (Python):**
- Any `*_document.py` whose module docstring contains the substring `"analytics functions"` (V69)
- `*_misc.py`, `*_helpers.py`, `*_utils.py` in `src/python/` (V50)

## Dimension 9: Public API Boundaries (Python)

- `__init__.py` uses EXPLICIT `__all__` (ZST is the reference implementation).
- The recommended dynamic pattern (18/20 packages):
  ```python
  import sys as _sys, types as _types
  _FF_API_EXCLUDE = frozenset({
      'Any', 'ClassVar', 'Dict', 'List', 'Optional', 'Path', 'Set', 'Tuple',
      'Union', 'dataclass', 'field', 'TYPE_CHECKING', 'annotations',
  })
  __all__ = [
      k for k in vars(_sys.modules[__name__])
      if not k.startswith('_')
      and not isinstance(getattr(_sys.modules[__name__], k), _types.ModuleType)
      and k not in _FF_API_EXCLUDE
  ]
  del _sys, _types
  ```
- Every exported symbol is intentionally public. No accidental leakage of typing imports,
  module objects, or `_private` symbols.
- `__init__.py` must be ≤100 LOC.

**Enforcing validators:** V65 (upgraded to FAIL in v2 for PRODUCT_SOURCE items).

## Dimension 10: Public API Boundaries (.NET)

- Every public type is in the package namespace.
- Internal types are `internal sealed`.
- No `public static` utility classes; use extension methods or factory methods.
- Every public method has `/// <summary>` XML doc comment.

## Dimension 11: Error Handling

- Every Python package defines its own exception hierarchy:
  ```
  {Format}Error(FormatFactoryError)
    {Format}ParseError({Format}Error)
    {Format}WriteError({Format}Error)
  ```
- `FileNotFoundError` is NOT caught and re-raised as a domain exception.
- Exceptions carry the offending offset or line number for format errors.
- Python exceptions live in `exceptions.py` (≤100 LOC).
- .NET exceptions live in `Exceptions/{Format}Exception.cs` (≤200 LOC each).

## Dimension 12: Test Requirements

Required test tiers per format:

| Tier | Name | Required count | What it tests |
|------|------|---------------|---------------|
| L0 | Smoke | ≥5 | Package importable, from_file works, exceptions defined |
| L1 | Unit | ≥20 | Parser returns correct domain model for valid input |
| L2 | Behavior | ≥30 | Writer roundtrip, analytics return correct values |
| L3 | Edge | ≥10 | Malformed inputs raise correct exceptions |

**Minimum total: 65 tests per format.**

Python tests: `.venv/Scripts/pytest tests/python/{format}/`
.NET tests: `dotnet test src/net/{format}/` (NOT pytest — .cs files are compiled by csproj)

## Dimension 13: Fixtures / Sample Files

- Real sample files MUST exist at `samples/by-format/{format}/valid/` (at least 2 files).
- Invalid/malformed sample files MUST exist at `samples/by-format/{format}/invalid/` (at least 1).
- No test may generate the ONLY sample file it tests (synthetic-only = L0 weakness per V36).

## Dimension 14: Governance Validators

New validators required in v2 (not present in v1):

**V69 `validate_analytics_naming_enforced`** — `blocks_sprint: True`
- Trigger: any `*_document.py` in `changed_files` under `src/python/`
- Logic: extract module docstring via `ast.get_docstring()`; if `"analytics functions"` is a
  substring of the docstring → FAIL
- Use substring check (`"analytics functions" in docstring`), NOT `startswith`
- ATOMIC DEPLOYMENT: V69 must deploy in the SAME sprint as both gnumeric and toml renames
  (TC-GM-002 + TC-GP-PY-001 + TC-GP-PY-004). Deploying first creates a permanent GOV_BLOCK.

**V70 `validate_dotnet_loc_cap`** — `blocks_sprint: True`
- Trigger: any `src/net/**/*.cs` file in `changed_files`
- Logic:
  - If file LOC ≤ 800 → PASS (new compliant files always pass)
  - If LOC > 800 AND file in `known_violations` → check for regression (LOC > baseline cap)
  - If LOC > 800 AND file NOT in `known_violations` → FAIL
- This resolves the decomposition catch-22: new `.cs` files ≤600 LOC pass automatically.

**V72 `validate_healing_stall_detector`** — `blocks_sprint: False` (advisory)
- Trigger: always (reads `registry/source-structure-baseline.json`)
- Logic: for each entry in `known_violations` where `loc == baseline_loc_cap` AND file exists
  on disk → WARN (zero healing progress since baseline was frozen)
- Does NOT read `remediation_deadline` — that field does not exist in the baseline JSON schema.

**Existing validators upgraded in v2:**
- V66 → `blocks_sprint: True` (was False)
- V65 → FAIL for `src/python/*/` PRODUCT_SOURCE items (was WARN)

## Monolith Healing Protocol (§8.1 from v1 — preserved)

When V35/V66/V69 GOV_BLOCK fires:

1. Identify the blocking file and its role mix.
2. Extract analytics functions to `{format}_analytics.py`.
3. Update imports in codec/parser: `try: from .{format}_analytics import *; except ImportError: pass`
4. If file still >800 LOC after analytics extraction: extract a second role to a new file.
5. Update `registry/source-structure-baseline.json` for any new files via:
   ```bash
   python tools/supervisor/update_source_baseline.py --path src/python/{format}/{file}.py
   ```
6. Run governance validators to confirm PASS before proceeding.

**GOV_BLOCK scope (CLAUDE.md §Supreme Directive):**
- `GOV_BLOCK:monolith_detection_validator` — V35
- `GOV_BLOCK:validate_source_architecture` — V66 (upgraded to block in v2)
- V69 and V70 added to GOV_BLOCK scope in CLAUDE.md via TC-GP-PLAN-001.

## Addendum: Python Packaging Requirements (TC-GFB-010, 2026-07-11)

Every Python format package MUST satisfy:

1. **`py.typed` marker file** — A `py.typed` empty marker file MUST be present at the package
   root (`src/python/{format}/{format}/py.typed`). This signals PEP 561 compliance for
   downstream type checkers.
2. **`pyproject.toml`** — Required fields: `[project]` with `name`, `version`, `description`,
   `requires-python`, `[project.optional-dependencies]` for test extras, and
   `[tool.setuptools.package-data]` including `"py.typed"`.
3. **Distribution targets** — Both sdist and wheel must be producible via `python -m build`.
4. **Round-trip compliance** — Parser → Writer round-trip MUST preserve all domain model fields.
   No silently dropped fields. Evidence: `dogfood_proof` artifact or dedicated roundtrip test.
5. **`__all__` declaration** — Every `__init__.py` must declare an explicit `__all__` list.

**Missing from existing compliance table:**
- `py.typed` presence: 0/20 formats confirmed (all likely missing marker — audit required)
- Round-trip test: 13/20 formats confirmed via oracle evidence
