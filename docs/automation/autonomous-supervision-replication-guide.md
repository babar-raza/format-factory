# Autonomous Supervision — Replication Guide

**Document type:** Automation — Operational Reference
**Created:** 2026-06-10
**Proven in:** FORMAT-FACTORY-AUTONOMY-NEXT-LEVEL-BROAD-MEGA-SPRINT-001 (12 consecutive autonomous sprints, 12,879 tests, 0 failures)

---

## 1. What Autonomous Supervision Is

Autonomous supervision is a file-based loop where an AI agent:
1. Reads its instructions from files generated by the previous sprint
2. Executes work (code, tests, fixes)
3. Writes an evidence declaration describing what it did
4. Runs a validation pipeline that grades the work
5. The pipeline generates new instruction files for the next sprint
6. The agent repeats — without human prompting

**The agent is stateless; the repository is stateful.** Every new window or session picks up from the same files. No memory of prior conversations is needed.

---

## 2. The 5 State Files That Drive the Loop

These files carry all state between sprints and across windows:

| File | Purpose | Written by | Read by |
|------|---------|-----------|---------|
| `reports/supervisor/session-resume.md` | Entry point for every session — last sprint outcome, test counts, what to do next | Supervisor (`autonomous-cycle`) | Agent (session start) |
| `reports/supervisor/approval-gates.md` | YES/NO decision on autonomous continuation, gate classification | Supervisor (`autonomous-cycle`) | Agent (before continuing) |
| `reports/supervisor/next-sprint.md` | Work items for the next sprint — the agent's task list | Supervisor (`autonomous-cycle`) | Agent (as sprint prompt) |
| `.local/evidences/<run_id>/evidence-declaration.yaml` | Machine-readable record of what the agent did — work items, test results, changed files | Agent (sprint closeout) | Supervisor (`autonomous-cycle`) |
| `.local/supervisor/continuation-signal.json` | Iteration counter and autonomous-continue flag | Supervisor (`autonomous-cycle`) | Agent (loop control) |

### State File Lifecycle

```
Sprint N ends:
  Agent writes evidence-declaration.yaml
  Agent runs autonomous-cycle
    → Supervisor reads declaration
    → Supervisor grades work items
    → Supervisor writes:
        session-resume.md       (for any future window)
        approval-gates.md       (YES/NO continue)
        next-sprint.md          (work for Sprint N+1)
        continuation-signal.json (iteration counter)

Sprint N+1 starts (same window OR new window):
  Agent reads session-resume.md    → knows current state
  Agent reads approval-gates.md    → checks if continuation allowed
  Agent reads next-sprint.md       → gets work items
  Agent executes work
  Agent writes evidence-declaration.yaml
  Agent runs autonomous-cycle
  → cycle repeats
```

## 3. How Cross-Window Recovery Works

When a Claude Code window exhausts its context or crashes:

1. The user opens a **new window** in the same repository
2. The agent reads `CLAUDE.md` (loaded automatically by Claude Code)
3. `CLAUDE.md` instructs: "Read `reports/supervisor/session-resume.md` at the start of every session"
4. `session-resume.md` contains: last sprint verdict, test counts, contradictions, and what to do next
5. The agent checks `approval-gates.md` for AUTONOMOUS_CONTINUE status
6. If YES → agent reads `next-sprint.md` and begins working
7. If NO → agent reports the blocker to the user

**No conversation history is needed.** The state files contain everything the agent needs to resume.

### What Makes This Possible

- `CLAUDE.md` is read automatically by every Claude Code session in this repo
- `session-resume.md` is regenerated by every `autonomous-cycle` run — always current
- `continuation-signal.json` tracks iteration count — prevents runaway loops
- `approval-gates.md` classifies every pending action as autonomous or human-required

## 4. The Autonomous Loop — Step by Step

### 4.1 Agent Reads Instructions

```
CLAUDE.md → "Read session-resume.md first"
  → session-resume.md → "Last sprint: ACCEPTED, Tests: 12879/0, AUTONOMOUS_CONTINUE: YES"
  → approval-gates.md → "AUTONOMOUS_CONTINUE: YES"
  → next-sprint.md → [19 work items with classifications]
```

### 4.2 Agent Executes Work

The agent performs tasks from `next-sprint.md`:
- Source code changes in `src/python/<format>/`
- Test creation in `tests/python/<format>/`
- Ledger updates in `reports/r90/product-code-change-ledger.json`
- Infrastructure work in `tools/supervisor/`

### 4.3 Agent Writes Evidence Declaration

At sprint end, the agent creates `.local/evidences/<run_id>/evidence-declaration.yaml`:

```yaml
run_id: "my-sprint-run-001"
sprint_id: "FORMAT-FACTORY-MY-SPRINT-001"
tests_run: 12879
test_results:
  passed: 12879
  failed: 0
  skipped: 62
  errors: 0
planned_work_items:
  - item_id: "WI-001"
    title: "Add export_to_csv to FODG"
    status: completed
    evidence_paths:
      - "src/python/fodg/fodg_codec.py"
    tests_supporting:
      - "tests/python/fodg/test_rNNN_fodg_csv_export.py"
completed_work_items: ["WI-001"]
worker_self_verdict: "ACCEPTED"
worker_self_grade: "PASS"
```

See `docs/automation/supervisor-worker-contract.md` for the full schema.

### 4.4 Agent Runs Autonomous Cycle

```bash
python tools/supervisor/supervisor_loop.py autonomous-cycle \
  --declaration .local/evidences/<run_id>/evidence-declaration.yaml
```

This single command:
1. Validates the declaration against schema
2. Inspects all declared evidence paths
3. Grades each work item (ACCEPTED / PARTIAL / REJECTED / OVERCLAIMED)
4. Runs anti-skip checks (detects hollow claims)
5. Runs governance validators
6. Generates `session-resume.md`, `approval-gates.md`, `next-sprint.md`
7. Writes `continuation-signal.json`
8. Returns exit code (0 = success, 3 = critical rework, 1 = invalid, 9 = error)

### 4.5 Agent Checks Continuation Conditions

All 5 must be true to continue:

1. Exit code was 0
2. `approval-gates.md` contains `AUTONOMOUS_CONTINUE: YES`
3. `continuation-signal.json` has `"autonomous_continue": true`
4. `iteration` < `max_iterations` in continuation-signal
5. No hard stop detected (push/commit needed, Gate approval needed)

If all true → go to step 4.1 with next-sprint.md as the new prompt.
If any false → STOP and report to user.

---

## 5. Hard Stops — What Always Requires a Human

These actions are never autonomous, regardless of continuation state:

| Action | Why it's a hard stop |
|--------|---------------------|
| `git commit` | Checkpoints shared history — must be intentional |
| `git push` | Affects remote — irreversible without force push |
| Gate 8 or Gate 11 approval | Human authority required by governance |
| Package publication (PyPI/NuGet) | Irreversible public release |
| MCP activation changes | Security-sensitive configuration |
| Destructive git operations | Data loss risk |

## 6. Iteration Limits and Safety

The `continuation-signal.json` file enforces loop bounds:

```json
{
  "autonomous_continue": true,
  "iteration": 5,
  "max_iterations": 12,
  "stop_reason": null
}
```

- Default `max_iterations`: 5 (configurable in `.supervisor/policies.yaml`)
- After max iterations: system stops with `stop_reason: max_iterations_reached`
- The agent reports the stop reason to the user and presents a summary
- The user can restart with a new max_iterations value

## 7. How to Replicate for a Different Project

The autonomous supervision pattern is project-agnostic. To implement it elsewhere:

### 7.1 Minimum Required Components

| Component | What to build | Format Factory equivalent |
|-----------|--------------|--------------------------|
| Session instructions file | Agent reads this automatically at session start; contains loop rules | `CLAUDE.md` |
| Resume file | Auto-generated summary of last sprint state | `reports/supervisor/session-resume.md` |
| Gate classifier | YES/NO decision on autonomous continuation | `reports/supervisor/approval-gates.md` |
| Next-work prompt | Machine-generated work items for the next sprint | `reports/supervisor/next-sprint.md` |
| Evidence declaration schema | YAML/JSON format the worker fills out declaring what it did | `.local/evidences/<run_id>/evidence-declaration.yaml` |
| Validation pipeline | Script that grades work items and writes continuation state | `tools/supervisor/autonomous_cycle.py` |
| Continuation signal | JSON with `autonomous_continue`, `iteration`, `max_iterations` | `.local/supervisor/continuation-signal.json` |

### 7.2 Minimal Implementation Steps

**Step 1: Create `CLAUDE.md` with loop instructions**

```markdown
## Session Start
Read `reports/session-resume.md` at the start of every session.

## After Reading session-resume.md
Check `reports/approval-gates.md`:
- AUTONOMOUS_CONTINUE: YES → proceed with next-sprint.md
- AUTONOMOUS_CONTINUE: NO → stop and report to user

## Sprint Closeout
1. Write evidence declaration at `.local/evidences/<run_id>/declaration.yaml`
2. Run: python tools/validate_and_grade.py --declaration <path>
3. Check exit code: 0 = continue, 3 = stop

## Autonomous Continuation
If exit code 0 AND approval-gates says YES AND iteration < max_iterations:
  Read next-sprint.md and begin next sprint.
  Repeat.
```

**Step 2: Create a validation script**

The validation script must:
1. Read the declaration YAML
2. Check that declared evidence paths exist
3. Check that tests pass (or at least that the declared test count is non-zero)
4. Grade each work item
5. Write `session-resume.md` with current state
6. Write `approval-gates.md` with YES/NO
7. Write `next-sprint.md` with forward work
8. Write `continuation-signal.json` with iteration counter
9. Return exit code 0 (continue) or 3 (stop)

**Step 3: Define what "evidence" means for your project**

In Format Factory, evidence includes:
- Source file paths with SHA-256 hashes
- Test file paths with pass/fail counts
- Sample output files
- Ledger entries

For a different project, evidence might be:
- API endpoint responses
- Screenshot comparisons
- Log file diffs
- Performance benchmarks

The key requirement: evidence must be **verifiable** (the validation script can check it exists and is non-empty).

**Step 4: Define hard stops**

Every project needs a list of actions that are never autonomous. At minimum:
- Any action that affects shared/remote state
- Any action that is difficult to reverse
- Any action that requires credentials or authorization

### 7.3 Optional Enhancements

These are not required for basic autonomous supervision but improve reliability:

| Enhancement | What it does | Format Factory tool |
|-------------|-------------|---------------------|
| Anti-skip checker | Detects overclaimed work (declared "completed" without evidence) | `anti_skip_checker.py` |
| Governance validators | Enforces project-specific rules beyond basic evidence checks | `governance_validators.py` |
| Evidence auto-packager | Generates 80% of the evidence declaration automatically | `evidence_auto_packager.py` |
| Stop-reason adjudicator | Classifies stop signals to prevent false external-gate blocks | `stop_reason_adjudicator.py` |
| Review package builder | Creates auditable ZIP bundles of all evidence | `build_declaration_review_package.py` |
| Bounded repair engine | Auto-repairs small test failures before marking work as failed | `bounded_repair_engine.py` |

## 8. How to Start an Autonomous Run

### 8.1 First Time (Cold Start)

1. Ensure `CLAUDE.md` exists with the loop instructions (see Section 7.2 Step 1)
2. Ensure `reports/supervisor/session-resume.md` exists (create manually or run one sprint first)
3. Open a Claude Code window in the repo
4. Tell the agent: "Continue with the next sprint" or "Run 5 autonomous sprints"

### 8.2 Continuing After a Window Closes

1. Open a new Claude Code window in the same repo
2. The agent will read `CLAUDE.md` automatically
3. The agent will read `session-resume.md` and pick up from where the last window left off
4. Say: "Continue" — the agent follows the loop

### 8.3 Continuing After Max Iterations

1. The agent stopped with `stop_reason: max_iterations_reached`
2. Review the summary the agent presented
3. If satisfied, say: "Continue for 5 more sprints"
4. The agent resets the iteration counter and resumes

### 8.4 Recovering After a Failure

1. If the last sprint had exit code 3 (critical rework):
   - `approval-gates.md` will show `AUTONOMOUS_CONTINUE: NO`
   - The agent will report the rework items
   - Fix the issues, then say "Continue"
2. If the last sprint had exit code 1 (invalid declaration):
   - The declaration YAML has schema errors
   - Fix the YAML and re-run `autonomous-cycle`
3. If the window crashed mid-sprint:
   - Open a new window
   - The agent reads `session-resume.md` from the LAST COMPLETED sprint
   - Any in-progress work from the crashed sprint is in the working tree
   - The agent can resume from the last known-good state

## 11. Key Design Principles

1. **Files carry state, not agent memory.** The agent is stateless. The repo is the database.
2. **Every sprint ends with a machine-readable declaration.** No implicit completion — everything is declared.
3. **The supervisor is advisory, not authoritative.** It grades and recommends — it cannot approve gates or push code.
4. **Hard stops are absolute.** The list of never-autonomous actions cannot be overridden by the supervisor.
5. **Iteration limits prevent runaway loops.** The system always stops after `max_iterations`.
6. **Cross-window recovery is automatic.** Any new window reads `session-resume.md` and resumes.
7. **The validation pipeline is deterministic.** Same declaration → same grades → same continuation decision.
8. **Evidence must be verifiable.** Declared paths must exist. Declared test counts must be non-zero. Overclaiming is detected and penalized.
