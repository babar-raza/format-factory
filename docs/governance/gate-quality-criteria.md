# Gate Quality Criteria

**Document type:** Policy
**Created:** R32 (2026-05-19)
**Authority:** This document defines minimum source, test, and evidence requirements for each gate.
**Motivation:** R32 state-drift investigation found that gate criteria allowed shallow probe parsers (141-217 LOC) to reach Gate 10 without write, export, or neutral model capability. This policy prevents future overclaiming.

---

## Principles

1. **Gate state must not outrank source/test evidence.** A gate is only as strong as the code and tests behind it.
2. **LOC is informational, not a hard gate.** Small code can be high quality. But LOC combined with missing capabilities (no model, no write) is a red flag.
3. **Read-only scope is valid only if explicitly approved.** Some formats (e.g., compression codecs) may not need write. This must be declared and approved, not assumed.
4. **Security gates (G7-G8) do not imply product maturity.** A parser can be secure but shallow.
5. **Gate advancement requires evidence, not reports.** Reports describe; source and tests prove.

---

## Gate Criteria

### Gate 1 — Candidate Scoring
- **Purpose:** Evaluate whether a format is worth acquiring.
- **Minimum evidence:** Completed scoring sheet (7-factor model), legal category classification.
- **Minimum source:** None.
- **Minimum tests:** None.
- **Required security:** Legal category must be classified; Category 5/6 automatic reject.
- **Allowed maturity class:** acquisition_only.
- **Disallowed claims:** No source claims, no parser claims, no product claims.

### Gate 2 — Spec and Legal Evidence
- **Purpose:** Retrieve and cache specification; establish legal basis.
- **Minimum evidence:** Spec cached with SHA-256 hash, legal notes, patent search or waiver.
- **Minimum source:** None.
- **Minimum tests:** None.
- **Required security:** Patent/IP risk assessment.
- **Allowed maturity class:** acquisition_only.
- **Disallowed claims:** No parser claims, no product claims.

### Gate 3 — Sample Corpus
- **Purpose:** Acquire or create valid sample files for the format.
- **Minimum evidence:** At least 3 valid samples + 1 intentionally invalid/edge-case sample. SHA-256 hashes recorded.
- **Minimum source:** None (samples may be generated by scripts but scripts are tools, not product source).
- **Minimum tests:** None (sample validation may use ad-hoc scripts).
- **Required security:** Samples must be project-owned or have clear licensing.
- **Allowed maturity class:** acquisition_only.
- **Disallowed claims:** No parser claims, no product claims.

### Gate 4 — Prototype Parser
- **Purpose:** Prove the format can be parsed programmatically.
- **Minimum evidence:** Working parser that reads at least header/structure from all Gate 3 samples.
- **Minimum source:** Parser file in prototypes/by-format/{format}/ or src/python/{format}/.
- **Minimum tests:** At least 10 test methods covering: valid parse, malformed input, size guard.
- **Required security:** File size guard must be present.
- **Allowed maturity class:** probe_only, read_only_prototype.
- **Disallowed claims:** No neutral model claims, no product claims, no packaging claims.
- **Promotion criteria:** Gate 4 pass allows a parser to exist. It does NOT imply library quality.

### Gate 5 — Neutral Model
- **Purpose:** Define a formal data model for the format's content.
- **Minimum evidence:** Neutral model schema or dataclass definitions with at least 5 modeled features.
- **Minimum source:** Neutral model file (neutral_model.py or equivalent). Parser must populate model fields.
- **Minimum tests:** At least 20 test methods covering: model construction, field validation, at least 3 feature-specific tests.
- **Required security:** Input validation for model fields (type checks, bounds).
- **Required corpus/spec proof:** Model entities must map to spec sections.
- **Allowed maturity class:** read_only_prototype, read_only_library_foundation.
- **Disallowed claims:** No write/export claims unless implemented. No product claims.
- **Stop condition:** If parser cannot extract enough features to populate 5+ model fields, Gate 5 cannot pass.

### Gate 6 — Oracle Comparison
- **Purpose:** Compare parser output against a reference implementation (e.g., LibreOffice).
- **Minimum evidence:** Oracle comparison report covering all Gate 3 samples.
- **Minimum source:** Oracle harness script + comparison script.
- **Minimum tests:** At least 10 test methods verifying parser-vs-oracle agreement.
- **Required security:** Oracle output must be generated in controlled environment.
- **Allowed maturity class:** read_only_prototype, read_only_library_foundation.
- **Disallowed claims:** No product claims.

### Gate 7 — Malformed/Fuzz Testing
- **Purpose:** Verify parser does not crash or corrupt on malformed input.
- **Minimum evidence:** At least 10 malformed/corrupted test fixtures, all handled gracefully.
- **Minimum source:** Fuzz fixtures in tests/fixtures/{format}/malformed/.
- **Minimum tests:** At least 15 test methods covering: truncated files, invalid headers, oversized dimensions, malformed structure, corrupt data.
- **Required security:** Parser must return error result (not crash/hang) for all malformed inputs.
- **Allowed maturity class:** read_only_prototype, read_only_library_foundation.
- **Disallowed claims:** Gate 7 pass does NOT imply product maturity.

### Gate 8 — Security Review
- **Purpose:** Formal security assessment of the parser.
- **Minimum evidence:** Security review report covering: XXE/DTD (XML formats), zip bombs (ZIP formats), decompression bombs (compressed formats), memory limits, resource exhaustion.
- **Minimum source:** No new source required, but security guards must be present in existing parser.
- **Minimum tests:** Security-specific tests must exist (separate from Gate 7 fuzz tests).
- **Required security:** All identified risks must be MITIGATED or DEFERRED with rationale.
- **Allowed maturity class:** Same as current. Gate 8 does NOT change maturity class.
- **Disallowed claims:** Gate 8 pass does NOT imply product maturity or library readiness. A secure probe is still just a probe.
- **Critical rule:** Gate 8 assesses security of what the parser does. It does NOT vouch for what the parser doesn't do.

### Gate 9 — Product Mapping
- **Purpose:** Map format features to product tiers; decide what goes in first release.
- **Minimum evidence:** Tier map (YAML) with feature-to-tier assignments. At least Tiers 0-2 defined.
- **Minimum source:** Source must implement at least Tier 0 features (basic parse + probe).
- **Minimum tests:** Tests must cover all Tier 0 features claimed.
- **Required security:** No new security requirements beyond Gate 8.
- **Allowed maturity class:** read_only_library_foundation or higher.
- **Disallowed claims:** Cannot claim Tier 2+ features without tests proving them.
- **Stop condition:** If parser is probe_only, Gate 9 can only be passed with explicit read-only-probe product scope approval.

### Gate 10 — OSS Release Readiness / Local Release Candidate
- **Purpose:** Verify format is ready for local package build and potential publication.
- **Minimum evidence:**
  - Source in src/python/{format}/ with: __init__.py, parser, neutral model (or approved exemption).
  - At least 50 test methods.
  - Local package build succeeds (pyproject.toml, build script).
  - README with API description.
- **Minimum source requirements (ONE of the following must be true):**
  - (a) Write/export capability implemented and tested, OR
  - (b) Round-trip capability verified, OR
  - (c) Explicit read-only release scope approved by project lead with rationale (e.g., compression codec where write is separate concern).
- **Minimum tests:** At least 50 test methods. Must include: parse, model, malformed, security, and at least one integration test with real corpus.
- **Required security:** All Gate 8 issues resolved or explicitly deferred with approval.
- **Allowed maturity class:** read_only_library_foundation (with approved read-only scope), read_write_library_foundation, export_capable_library, roundtrip_capable_library.
- **Disallowed claims:** probe_only or read_only_prototype CANNOT pass Gate 10.
- **Critical rule:** A parser that only extracts metadata/header without full content parsing cannot be a release candidate unless product scope explicitly limits to probing.

### Gate 11 — Commercial Readiness
- **Purpose:** Verify .NET commercial implementation meets capability model requirements.
- **Minimum evidence:**
  - .NET source in src/net/{format}/ with: Parser, Document (Load/Save), Model classes, at least 1 Exporter.
  - C4+ capability (load-edit-save minimum).
  - At least 100 .NET test methods.
  - Round-trip tests (load-edit-save-reload).
  - Security review for .NET implementation.
  - G11-G human approval packet.
- **Minimum source:** Complete .NET project with .csproj, model classes, exporters.
- **Required security:** DTD prohibition, XmlResolver null, size guards, entity expansion limits.
- **Allowed maturity class:** commercial_candidate, production_track_real.
- **Disallowed claims:** commercial_product_ready CANNOT be true without G11-G human approval.
- **Human approval required:** G11-G must be approved by project lead (Babar Raza). No delegation.

---

## Retroactive Assessment

Formats that passed gates before this policy was established are NOT automatically demoted. However, the format-completion-matrix.yaml records an `evidence_backed_gate` that reflects what the source and tests actually support under these criteria. Future gate advancement must comply with this policy.

---

## Enforcement

1. `tests/evidence/test_gate_quality_claims.py` validates that no format claims a gate without meeting these criteria.
2. The completion matrix records both `claimed_gate` and `evidence_backed_gate`.
3. Sprint reports must reference this policy when advancing gates.
4. Gate corrections (reducing evidence_backed_gate) require a DRIFT-* taskcard and human review.
