## 2. PYTEST INVOCATION — WINDOWS USER SITE-PACKAGES

pytest and jsonschema are in user site-packages, not the system Python path.

**Correct invocation (subprocess/script):**
```python
import site; site.addsitedir(site.getusersitepackages())
import pytest
pytest.main(["tests/...", "-q"])
```

**Correct invocation (shell — wraps in subprocess):**
```bash
python -c "import site; site.addsitedir(site.getusersitepackages()); import pytest; pytest.main(['tests/', '-q'])"
```

**Do NOT use:**
- `python -m pytest` without PYTHONPATH set (fails: no module named pytest)
- `PYTHONPATH=.` alone (this only adds repo root, not user site-packages)

**For scripts invoked as subprocesses (like run_ai_checks.py):**
Add at the top of the script:
```python
import site as _site
_site.addsitedir(_site.getusersitepackages())
```

And for subprocess.run calls inside scripts:
```python
import os, site
_SUBPROCESS_ENV = dict(os.environ, PYTHONPATH=os.pathsep.join(
    filter(None, [str(REPO_ROOT), site.getusersitepackages(), os.environ.get("PYTHONPATH", "")])))
# Pass env=_SUBPROCESS_ENV to subprocess.run(...)
```

## 9. WHEN TESTS FAIL

1. Run the failing test with `--tb=long` to get full traceback
2. Check if it's a pre-existing failure (compare with previous sprint verdicts)
3. If pre-existing: classify and document, do NOT attempt to hide
4. If new: fix root cause, do NOT work around with --no-verify or skip markers
5. Re-run to confirm fix
