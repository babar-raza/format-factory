## Root causes

### Competing partial authorities

Contracts, SAL facts, registries, package proof, oracles, taskcards, the global
plan-control engine, and the FF6 controller each describe part of reality. They
do not share one dependency-closed proof graph or one task projection.

### Evidence identity is incomplete

Legacy evidence does not always bind authority, source, test, corpus,
dependency lock, environment, tool, package, and external oracle into one
immutable result. A source digest can remain current while the result is stale.

### Presence has been treated as behavior

Files, methods, exports, generated classes, fixtures, and test names have been
used as proxies for executed normative behavior. This rewards breadth-shaped
artifacts without proving correctness, preservation, or rejection.

### Task generation is disconnected from obligations

The FF6 journal now selects an exact authority-closure repair, but the global
queue can still select a legacy broad NRRD/OpenRaster task. The global
projection does not consume the FF6 program task dependencies. This remains a
rerun-consistency risk outside the journaled FF6 path.

### Authority acquisition is status-shaped, not replay-shaped

Contracts say `ACQUIRED`, while the required bytes live only under ignored
local paths or have no path/digest at all. There is no unified legal,
redistribution, lock, cache, fetch, and offline verification contract. Historic
labels therefore survive after their inputs disappear.

The event-14 WIP starts the structural repair, but it is not yet wired into the
source researcher, ProductContract compiler, stores, or capability compiler.
Until that wiring and replay pass, the old failure mode remains operational.

### Provider shifts previously occurred above the durable state plane

Earlier handovers pointed to a clean older commit while newer implementation
existed only in one provider's worktree. That creates two plausible resume
points and encourages either data loss or duplicate work. The repair is to
record a truthful `WORK_IN_PROGRESS` controller event, commit the bounded
tested slice to GitLab main, include exact output digests, and transfer
coordination ownership. A chat summary is never part of the resume key.

### Mutable execution context

Shared worktrees, source-tree imports, non-locked dependencies, editable
fixtures, and line-ending-dependent hashes make identical-looking runs consume
different inputs.

### Package architecture grew before production contracts

The five packages accumulated useful functionality, but their stable public
surface, preservation rules, error semantics, optional dependency boundaries,
performance budgets, and compatibility policies were not compiled from a
complete capability contract first.

## Structural weaknesses to redesign

- Promote one canonical product contract and proof graph; make other views
  derived projections.
- Compile capability and obligation inventories from pinned primary
  authorities, not hand-maintained feature lists.
- Make task selection consume the current obligation projection and FF6 program
  dependencies.
- Declare digest canonicalization and prefer Git blob/tree identities for
  tracked text.
- Bind installed-wheel execution to exact locks and environment manifests.
- Make corpus and oracle independence explicit, licensed, and digest-bound.
- Separate generated schema source from handwritten workflows.
- Require fresh detached worktrees or containers for certification.
- Make promotion computed and revocable when any dependency changes.
- Make every provider boundary a remote-verifiable event/task/proof checkpoint;
  a provider name or token budget must not alter task semantics or reopen
  completed substeps.

## What must be preserved

- Existing working source and tests.
- Characterization behavior needed for safe API migration.
- Format contracts, SAL facts, official schemas, and acquisition history.
- The append-only historical gap and coordination records.
- GitLab-main consolidation and the implicit `format_factory` namespace.
- Security limits, preservation behaviors, strict validation, and adapters that
  already work and can be independently proven.

## What must not be preserved as authority

- Legacy readiness labels.
- Passing package-smoke reports with stale dependency closure.
- D0 partial oracle verdicts.
- Old branch names and deleted worktree identity.
- Broad taskcards that skip program dependency gates.
- Raw checkout-byte hashes without a declared canonicalization policy.
- An agent's prose summary, including this document.

## Limits and uncertainty

The current inventory is strong enough to disprove production readiness and to
drive bounded repair, but it is not yet a complete primary-spec audit. The
636-obligation count is exact for the current contracts, not proof that those
contracts capture every stable requirement. OpenRaster authority is especially
weak because the specification is an evolving draft. UBL and XLIFF breadth
will be large and generator-heavy; reproducibility and schema
cross-validation will cost more than handwritten subsets. Full cross-platform,
fuzz, mutation, and performance certification will require substantial compute
and external tools.
