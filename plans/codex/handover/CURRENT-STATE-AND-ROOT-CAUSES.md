# Current State, Root Causes, and Structural Weaknesses

## What has actually been achieved

The mission has a hardened production plan, an immutable six-product goal, a
clean GitLab-main baseline, a digest-bound product snapshot, a four-event
controller journal, and one completed program taskcard.

Five Python packages contain meaningful source and tests:

| Format | Source depth observed | Evidence limitation |
|---|---|---|
| IPYNB | Broad typed model, codec, validation, conversion, cleanup, trust inspection, editing | Oversized public initializers, D0 oracle, stale proof-input closure, no production certification |
| NRRD | Header/payload codec, attached and detached entry points, encodings, preservation, limits | Model remains string/dictionary heavy, D0 oracle, stale proof-input closure |
| XLIFF | Core document model, inline editing, segmentation, translation-state helpers, preservation | Complete typed 2.1 module vocabulary is absent, D0 oracle, stale proof-input closure |
| SafeTensors | Compact typed descriptors, strict layout validation, mmap/region access, writer, adapters | Differential proof and corpus depth remain shallow; proof-input closure is stale |
| UBL | Ninety-one generated root subclasses, ordered generic XML model, extension and signature handling | Roots are not backed by a fully schema-typed component/cardinality model; proof remains shallow |
| OpenRaster | Contract and SAL planning artifacts only | No source package, product tests, corpus, oracle, or install proof |

These are implementation footholds, not production-ready libraries.

## What has not been achieved

- No complete per-format capability universe exists.
- No complete normative obligation inventory exists for any selected format.
- No mandatory obligation has current end-to-end proof coverage.
- No selected package has production certification.
- No OpenRaster product package exists.
- No current installed-wheel matrix covers Linux, Windows, macOS and Python
  3.11 through 3.14.
- No complete independent corpus and external-oracle suite exists.
- No standalone repository extraction and re-certification has passed.
- No release candidate or release has been produced.

## Symptoms

1. Reports say PASS while their complete input closure is stale.
2. Capability counts and public symbol counts are mistaken for format depth.
3. Existing oracles execute one shallow case and mark the rest not applicable.
4. Clean source-tree tests depend on accidental environment installation.
5. Several package initializers violate the architecture limits.
6. Old plans and global queue selection disagree with the FF6 controller.
7. Raw digest comparisons change across Windows checkouts.
8. Historical coordination conflicts remain open after branches and worktrees
   were consolidated.

## Root causes

### Competing partial authorities

Contracts, SAL facts, registries, package proof, oracles, taskcards, the global
plan-control engine, and the FF6 controller each describe part of reality. They
do not share one dependency-closed proof graph or one task projection.

### Evidence identity is incomplete

Legacy evidence does not always bind authority, source, test, corpus,
dependency lock, environment, tool, package, and external oracle into one
immutable result. A source digest can remain current while the result is stale.

### Presence has been treated as behavior

Files, methods, exports, generated classes, fixtures, and test names have been
used as proxies for executed normative behavior. This rewards breadth-shaped
artifacts without proving correctness, preservation, or rejection.

### Task generation is disconnected from obligations

The current global queue can select a broad NRRD/OpenRaster implementation task
before the mandated six-format capability compilation. The FF6 program task is
not consumed by that queue. This is why reruns choose different work.

### Mutable execution context

Shared worktrees, source-tree imports, non-locked dependencies, editable
fixtures, and line-ending-dependent hashes make identical-looking runs consume
different inputs.

### Package architecture grew before production contracts

The five packages accumulated useful functionality, but their stable public
surface, preservation rules, error semantics, optional dependency boundaries,
performance budgets, and compatibility policies were not compiled from a
complete capability contract first.

## Structural weaknesses to redesign

- Promote one canonical product contract and proof graph; make other views
  derived projections.
- Compile capability and obligation inventories from pinned primary
  authorities, not hand-maintained feature lists.
- Make task selection consume the current obligation projection and FF6 program
  dependencies.
- Declare digest canonicalization and prefer Git blob/tree identities for
  tracked text.
- Bind installed-wheel execution to exact locks and environment manifests.
- Make corpus and oracle independence explicit, licensed, and digest-bound.
- Separate generated schema source from handwritten workflows.
- Require fresh detached worktrees or containers for certification.
- Make promotion computed and revocable when any dependency changes.

## What must be preserved

- Existing working source and tests.
- Characterization behavior needed for safe API migration.
- Format contracts, SAL facts, official schemas, and acquisition history.
- The append-only historical gap and coordination records.
- GitLab-main consolidation and the implicit `format_factory` namespace.
- Security limits, preservation behaviors, strict validation, and adapters that
  already work and can be independently proven.

## What must not be preserved as authority

- Legacy readiness labels.
- Passing package-smoke reports with stale dependency closure.
- D0 partial oracle verdicts.
- Old branch names and deleted worktree identity.
- Broad taskcards that skip program dependency gates.
- Raw checkout-byte hashes without a declared canonicalization policy.
- An agent's prose summary, including this document.

## Limits and uncertainty

The current inventory is strong enough to disprove production readiness, but it
is not yet a complete spec audit. Capability totals must not be guessed from
the present contract record counts. OpenRaster authority is especially weak
because the specification is an evolving draft. UBL and XLIFF breadth will be
large and generator-heavy; reproducibility and schema cross-validation will
cost more than handwritten subsets. Full cross-platform, fuzz, mutation, and
performance certification will require substantial compute and external tools.
