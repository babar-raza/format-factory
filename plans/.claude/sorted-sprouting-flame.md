# Plan: PROJECT_STATUS.md Generator Audit, Two-Lane Hardening, and Idempotent Closure

**Plan ID:** sorted-sprouting-flame
**Type:** machinery_hardening
**Status:** IN_PROGRESS

## Context

`PROJECT_STATUS.md` is the canonical auto-generated project status document referenced from the root `README.md`. It is generated by `tools/docs/generate_project_status.py` which orchestrates four sub-generators. The current document mixes **machinery** (governance validators, capabilities, skills, supervisor, agent ecosystem) and **product** (format implementations, oracle results, certification, gates) concerns in ways that mislead external readers, produce misleading aggregations, and allow autonomous regeneration to alter the document's structure without detection.

The specific problems to fix:
1. Machinery and product statistics share a single flat table with no lane separation
2. Architecture section embeds governance validators, capabilities, skills, gates — none of which belong under "Architecture Layer Inventory"
3. Several claims have wrong denominators (certification "20/20" excludes 4 untracked formats; oracle "20" of 24 tracked)
4. L09 State Layer file count (56,348) is gitignored local state — misleading to external readers
5. `gate_8_approval` listed as a hard prohibition but Gate 8 is agent-executable in the gate table — direct contradiction
6. `checkpoint_interval` renders as "N/A" — missing policy read path
7. "15 unclassified capabilities" in capability track table — unexplained
8. No tests exist for any of the five generator files
9. No autonomous enforcement prevents drift: no governance validator, no pre-commit hook, no freshness check
10. README injection block has stale quick-numbers (101 validators, 120 skills vs actual 92, 102)
11. Atomic write not implemented — generator failure can produce partial output
12. No explicit stable anchors — heading-derived anchors break on any rename

The fix must happen **at the generator level**, not by manually editing `PROJECT_STATUS.md`.
