# Repository Root Folder Reconnaissance Plan

## Problem Statement

The format-factory repository has **51 top-level directories**. There is no machine-readable catalog of what they are, why they exist, or who owns them. Only 4 folders have `README.md` and 5 have `_readme.md` — **42 folders are undocumented**. No validator enforces folder registration, README presence, or format coverage. Several folders show evidence of redundancy or abandonment (e.g., `state/` duplicates `.supervisor/state/`, `drivers/` has zero consumers, `skills/` is redundant with `.supervisor/skill-registry.yaml`). Without governance, new top-level folders appear without documentation, stale folders persist, and agents cannot reliably determine where files belong.

**What's broken:** No folder registry, no README governance, no format-coverage contract, no drift detection. Agents and humans navigate by convention and memory, which degrades across sessions.

**What this plan produces:** A durable, validated, idempotent folder governance system: registry + validator + documented READMEs + format coverage audit + regression tests.

## Structural Consistency Breakers (What Would Break Reruns)

1. **No single source of truth for "which folders should exist"** — classification lives only in this plan, not in a machine-readable registry. Any rerun must re-derive classifications from scratch.
2. **README backfill has no idempotency mechanism** — creating READMEs is not idempotent; a second run would either skip (already exists) or overwrite. Need BEGIN/END markers for generated sections, and a "create only if missing" policy for the file itself.
3. **Format coverage audit has no baseline to diff against** — without a committed coverage snapshot, each run produces a fresh report with no way to detect drift vs. baseline.
4. **Validator runs against live filesystem** — if folders are added/removed between runs, results change. The registry must be the contract, not the filesystem.
5. **_readme.md vs README.md naming inconsistency** — existing convention uses `_readme.md` for directory-orientation docs. Renaming to `README.md` would break convention without adding value.

**Mitigation:** The registry (`repository-root-folders.yaml`) becomes the durable contract. The validator checks filesystem against registry. READMEs use "create if missing" + BEGIN/END for generated sections. Coverage baselines are committed.

**Validator function signature (MUST match existing pattern):**
```python
def validate_root_structure(declaration: dict, repo_root: "Path | None" = None) -> dict:
```

**Checks:**
1. **Registry completeness** — every top-level directory on disk appears in `registry/repository-root-folders.yaml` (or has `retention: EXEMPT`). Result: FAIL + `blocks_sprint=True` for unregistered directories.
2. **README presence** — every entry with `readme_required: true` has the file specified by `readme_convention`. Result: WARN for missing.
3. **Resurrection detection** — any entry with `retention: DELETED` must not exist on disk. Result: WARN.
4. **Format coverage contract** — entries with `format_scoped: true` are checked against `reports/repository-structure/format-folder-coverage.yaml`. Result: WARN for new gaps.
