# Supervisor Verdict Packet Model

Sprint ID: FORMAT-FACTORY-REQUIREMENT-CAPABILITY-AUTHORITY-LAYER-PRODUCTION-BLOCKER-HEALING-001
Owner: Lane D

## 16-Field Normalized Packet Specification

The SupervisorVerdictPacket is a machine-readable JSON file (supervisor-verdict-packet.json)
generated by SupervisorVerdictPacketGenerator. Supervisor must consume this file as primary input
and must not infer readiness from prose reports alone.

### Field 1: packet_id
- Type: string
- Description: Unique identifier for this packet. Format: svp-{sprint_id}-{timestamp}
- Required: true

### Field 2: generated_at
- Type: ISO8601 datetime string
- Description: When the packet was generated
- Required: true

### Field 3: source_graph_hash
- Type: sha256 hex string (64 chars)
- Description: SHA-256 of the sorted capability-graph-nodes.jsonl + capability-graph-edges.jsonl content used to generate this packet. Supervisor can verify graph integrity.
- Required: true

### Field 4: claims_checked
- Type: integer
- Description: Total number of CapabilityClaim nodes evaluated in this packet
- Required: true

### Field 5: coverage_records
- Type: array of CoverageRecord summaries
- Description: One entry per evaluated claim: {claim_id, status, missing_proof_types, product_id, family}
- Required: true

### Field 6: overclaim_risks
- Type: array of {claim_id, pattern_number, recommended_remediation}
- Description: Claims flagged by OverclaimDetector with remediation recommendation
- Required: true (empty array if none)

### Field 7: stale_claims
- Type: array of {claim_id, stale_reason, stale_since}
- Description: Claims in stale state or backed by stale nodes
- Required: true (empty array if none)

### Field 8: unsupported_features
- Type: array of UnsupportedFeature summaries
- Description: All declared UnsupportedFeature nodes: {feature_name, severity, claim_id}
- Required: true (empty array if none)

### Field 9: poc_readiness_verdict
- Type: object
- Description: Per-target readiness: {target_product: "fods", status: "COVERAGE_NEEDED" | "ACCEPTED_FOR_POC" | "ACCEPTED_WITH_LIMITATIONS" | "BLOCKED", blocking_claims: [...]}
- Required: true

### Field 10: mainstream_gap_queue_ref
- Type: string (file path, relative to repo root)
- Description: Path to mainstream-gap-queue.json generated for this graph snapshot
- Required: true

### Field 11: recommended_supervisor_decision
- Type: enum (see 9 decision values below)
- Description: Machine-computed recommendation based on graph state. Supervisor may accept or override.
- Required: true

### Field 12: false_pass_risks
- Type: array of {risk_description, affected_claim_id, risk_type}
- Description: Cases where a PASS might be inferred incorrectly without the graph layer
- Required: true (empty array if none)

### Field 13: false_stop_risks
- Type: array of {risk_description, affected_claim_id, risk_type}
- Description: Cases where a valid partial claim might be incorrectly blocked by the evaluator
- Required: true (empty array if none)

### Field 14: stream_consumption_status
- Type: object
- Description: Which streams have consumed this packet: {mainstream: true|false, skills: true|false, acceleration: true|false, supervisor: true|false}
- Required: true

### Field 15: external_tool_boundary
- Type: string
- Description: Statement of which external tools were used (if any) in graph construction; must declare any ai_draft sources
- Required: true

### Field 16: evidence_package_refs
- Type: array of {package_id, sha256, materialized, claim_links}
- Description: All EvidencePackage nodes referenced in this packet
- Required: true (empty array if none)

## 9 Supervisor Decision Values

1. **ACCEPT_PRODUCT_PROGRESS** — All required claims are coverage_validated; no blocking issues; Mainstream can commit
2. **ACCEPT_WITH_LIMITATIONS** — Required claims accepted_with_limitations; UnsupportedFeature records present and visible; acceptable for POC
3. **REJECT_OVERCLAIM** — One or more claims are overbroad; decomposition required before acceptance
4. **BLOCK_MISSING_DOGFOOD** — Required DogfoodProof missing for dogfood_required capability families; cannot accept without it
5. **BLOCK_MISSING_REQUIREMENT** — No accepted ProductRequirement linked to one or more claims; requirement must be sourced first
6. **BLOCK_STALE_PROOF** — One or more stale dependencies (requirement, test, dogfood) prevent acceptance; revalidation required
7. **CONTINUE_MAINSTREAM_WITH_GAP_QUEUE** — Claims are partially proven; Mainstream should continue with the gap queue entries provided
8. **CONTINUE_WITH_REROUTE** — Current POC target is blocked; Mainstream should reroute to a different target's gap queue
9. **NEEDS_POLICY_DECISION** — One or more claims require ProductPolicyDecision; cannot proceed until human decision is recorded

## False Pass Risks (≥4)

1. **evidence_package_present_but_claim_not_graph_linked** — An EvidencePackage exists and has a valid checksum, but no claim_links connect it to a CapabilityClaim. The package proves file integrity but not capability coverage. Without the graph layer, this looks like PASS.

2. **test_passes_but_not_linked_to_claim** — Test files exist in tests/ and pass locally (via dotnet test or pytest), but no tested_by edge in the graph links them to the capability claim. Coverage appears validated but is not recorded in any CoverageRecord.

3. **poc_targets_shows_pass_but_requirement_stale** — poc-targets.yaml shows status=PASS for a target (imported from a prior sprint). The backing ProductRequirement has since become stale. The dashboard looks green; the graph shows blocked.

4. **dogfood_output_exists_but_not_validated** — A .ppm or .fods file exists in examples/ with the right format. It was not produced by the canonical implementation path; it was hand-crafted or produced by a different tool. No validator_used recorded; checksum not linked to DogfoodArtifact node.

5. **context_pack_used_as_claim_proof** — A ContextPackRef from a prior sprint snapshot is present. A consumer interprets the context pack's capability list as proof of current readiness. Context packs are informational; they are not CoverageRecords.

## False Stop Risks (≥3)

1. **overclaim_detection_flagging_valid_partial_claim** — OverclaimDetector identifies a claim as overbroad because the claimed scope (all_variants) exceeds current evidence. The valid partial claim (P3_only) is valid and could be accepted. Without decomposition, the entire claim is blocked. The system must split rather than reject.

2. **staleness_flagging_already_recomputed_records** — StalenessInvalidationEngine flags a CoverageRecord as stale because a source file mtime was updated. The update was a whitespace-only formatting change; the behavior is identical. The system demotes the claim unnecessarily. FreshnessProof should note recomputed records where behavior was unchanged.

3. **empirical_only_requirement_blocking_acceptable_poc_claim** — A ProductRequirement is classified as empirical_only because no formal ODF spec section has been imported as SpecRequirementRef. The empirical evidence (actual .fods file sample) is perfectly valid for POC purposes. The evaluator must allow empirical_only requirements to satisfy POC claims with a visible caveat, not block them outright.
