## Critical Risk Summary

The most dangerous integration gap is that **implementations can reach Gate 11 and be
packaged for release without any spec fact traceability**. The following domino effect
is possible today:

1. Format selected for implementation (task selector uses synthetic spec artifacts)
2. Parser built empirically (no spec fact refs in code)
3. Tests pass (empirical, not spec-driven)
4. Evidence declared ACCEPTED (no spec_fact_refs required)
5. Proof graph shows spec_auth test node passes (tests pass, but they test the tool, not the format)
6. Gate 11 approved (no spec_coverage check in gate criteria)
7. Package released

This chain is not hypothetical — it describes the current state for most formats.
FODS is the closest to a real spec-backed implementation, but even FODS lacks
code-level spec fact citations.

## Positive Findings

Despite the gaps above, several strong controls are in place:

1. **Anti-bypass governance is real**: spec_governance_runtime.py enforces registration
   and citation rules; tests prove it works.
2. **T3 download authorization is procedural but real**: FODS has a real spec PDF with
   documented T3 authorization.
3. **Requirements validation blocks AI-only proposals**: validate_generated_requirements.py
   prevents AI-generated requirements from being accepted without source evidence.
4. **Staleness detection exists**: refresh_check.py and staleness_invalidator can detect
   stale specs when run.
5. **Context packs are SHA-256 bound**: context_pack_builder verifies SHA before use.
