# Lane G: Downstream Product-Generation Layers Audit
# Sprint: ff-machinery-readiness-audit-20260625

## Layer Map

The downstream pipeline from spec to product code has 6 layers:

```
Layer 1: Spec Authority (SAL)      → PARTIAL (3/20 tools active)
Layer 2: Capability Derivation      → OPERATIONAL but unconsumed
Layer 3: Feature Planning           → BROKEN (hardcoded _EXPANSION_GOALS)
Layer 4: Code Generation            → MANUAL (FeatureFactory not called)
Layer 5: Governance/Validation      → STRONG (48 validators)
Layer 6: Evidence & Continuation    → STRONG (autonomous_cycle.py)
```

**The pipeline breaks at Layer 3.** Products are generated by agents responding to next-sprint.md
prompts (which are generated by Layer 6) — NOT driven by spec facts or capability gaps.

---

## Layer 3: Feature Planning — The Primary Failure Point

### autonomous_task_generator.py (direct evidence)

```python
# Line 5-11 (docstring):
# Generates queue-item-v2 product task candidates from:
# 1. Capability expansion targets (predefined per-format expansion goals)   ← HARDCODED
# 2. Capability gap ledger (reports/capability-layer/gap-ledger.json)       ← secondary
# 3. Source code introspection (detects missing functions)                   ← tertiary

# Line 29+: _EXPANSION_GOALS list
_EXPANSION_GOALS: List[Dict[str, Any]] = [
    {"format": "fodg", "function_name": "export_to_csv", "spec_authority": "schema_authority_available", ...},
    {"format": "tsv", "function_name": "append_row", "spec_authority": "no_public_spec_available", ...},
    {"format": "ndjson", "function_name": "validate_schema", "spec_authority": "no_public_spec_available", ...},
    # ... 20+ more entries
]
```

**Critical observation:** Many entries have `"spec_authority": "no_public_spec_available"` —
meaning the task was created WITHOUT a spec-backed justification. This directly causes:
- Work items without `spec_fact_refs` (TC-GUARD-001 BLOCK mode)
- Products that implement features that aren't in the spec
- Features that don't trace to any verifiable capability

**This is the root cause of non-repeatable, non-spec-driven product deepening.**

### generate_next_worker_prompt.py

This generates the prose sprint prompt from:
- Prior sprint work items (from declaration)
- Gap ledger entries (advisory)
- Supervisor state

The generated prompt is advisory. It recommends work but cannot enforce spec compliance
without the feature planning layer correctly driving it.

## Layer 4: Code Generation — Manual Only

### FeatureFactory (product_feature_factory.py, lines 1-100)

```python
# 6 patterns:
# A: Getter    — apply_getter(source_path, function_name, return_type, ...)
# B: ExportCsv — apply_export_csv(source_path, function_name, ...)
# C: Roundtrip — apply_roundtrip_test(source_path, ...)
# D: Append    — apply_append(source_path, function_name, ...)
# E: Probe     — apply_probe(source_path, function_name, ...)
# F: PackageProof — apply_package_proof(source_path, ...)
```

**Status:** The class is fully implemented and functional. But:
1. It requires a human (or skill) to invoke it with specific parameters
2. It does NOT derive parameters from spec facts or gap-ledger entries
3. It does NOT enforce spec_qname in generated function bodies
4. It is NOT called by autonomous_task_generator.py or autonomous_cycle.py
5. It is NOT connected to the skill framework (no /feature-factory slash command)

**Where malformed code comes from:** When agents implement features without this tool
(direct file editing per next-sprint.md prompts), they may:
- Create functions without spec_fact_ref linkage
- Use non-QName-compliant naming
- Mix analytics into codec files (analytics masquerade)
- Create functions with no gap-ledger backing

The FeatureFactory patterns (A-F) would prevent these issues if used consistently,
but there's no enforcement mechanism requiring their use.

|---|---|

| V36 (stub tests) | Tests with >80% weak assertions |

| TC-GUARD-002 (purpose check) | Items classified as UNPURPOSEFUL |
| V42 (deepening suspension) | Products with _mod_N_times_M arithmetic patterns |

**Assessment:** STRONG governance at the output end. These validators DETECT violations
AFTER they're submitted in a declaration. They don't PREVENT the violation from being coded.

**Gap:** No pre-generation governance. Validators run post-declaration, not pre-coding.
The missing pre-sprint hook (GAP-SKILL-004) would close this gap.

**This is the strongest part of the downstream pipeline.** The evidence and continuation

- 19-state machine (YES, YES_WITH_LIMITATIONS, YES_WITH_REWORK, NO_*)

**But it's downstream of the broken feature planning layer.** When Layer 3 generates
unconstrained work items (from _EXPANSION_GOALS), Layers 5-6 can detect and block them
via TC-GUARD-001, but the net effect is: many work items are reworked or rejected,
slowing the autonomous loop.

## Where Malformed Code Is Introduced

Three pathways produce non-QName-compliant, non-spec-driven code:

**Pathway 1: Agents responding to generic next-sprint.md prompts**
- Sprint prompt says "advance product deepening for format X"
- Agent implements a function without gap_ledger_ref
- TC-GUARD-001 rejects it in next sprint cycle
- Developer fixes it manually and re-declares

**Pathway 2: _EXPANSION_GOALS with no_public_spec_available**
- Task generator recommends a function with spec_authority=no_public_spec_available
- Agent implements it; declaration includes spec_fact_refs=[]
- TC-GUARD-001 adds it to rework_items
- Work item eventually dropped or given provisional fact

**Pathway 3: Manual ad-hoc src/ edits (bypass)**
- Agent edits src/ directly without using a skill
- product_code_ledger_required_before_source_edit control catches this
- But: the control is in skill-registry.yaml (advisory) — no code enforces it pre-edit

## Downstream Layer Audit Verdict

| Layer | Status | Evidence |
|---|---|---|
| Spec Authority (SAL) | PARTIAL | 3/20 tools active; 17 dormant |
| Capability Derivation | OPERATIONAL/ISOLATED | Output generated; never consumed |
| Feature Planning | BROKEN | Hardcoded _EXPANSION_GOALS; gap-ledger ignored |
| Code Generation | MANUAL/UNCONNECTED | FeatureFactory exists; not called by loops |
| Governance/Validation | STRONG | 48 validators; TC-GUARD-001 in BLOCK mode |
| Evidence & Continuation | STRONG | 19-state machine; session guards; circuit breaker |

**Root cause of non-repeatable product deepening:** Feature planning (Layer 3) is broken.
All other layers compensate for it (validators detect violations, continuation loop
retries rework items) — but compensation is not prevention. Without fixing Layer 3,
every autonomous sprint requires manual rework to meet governance standards.
