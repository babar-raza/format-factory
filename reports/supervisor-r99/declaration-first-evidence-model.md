# Train B: Declaration-First Evidence Model

## Problem
The supervisor system was designed around two incompatible models:
1. **Legacy ZIP model** (R56-R86): Worker builds a ZIP bundle, validator runs against contract YAML
2. **Declaration model** (R88+): Worker writes evidence-declaration.yaml, supervisor inspects worktree

After R88, the declaration model became canonical, but the legacy model's artifacts (session-resume.md, approval-gates.md, next-sprint.md, contradictions.md) were never regenerated by the declaration cycle. This created D99-STALE-01: the most-read supervisor outputs showed stale R86 data while the actual state was R98 ACCEPTED.

## Root Cause
`autonomous_cycle.py` wrote bridge JSON (evidence-review.json, contradictions.json) but never called `generate_supervisor_packet.py` to regenerate the markdown outputs that agents and humans read.

## Fix Applied (R99)
1. Added Step 2c: materialize_declared_evidence() — captures diffs, SHAs, source snapshots
2. Added Step 7b: generate_supervisor_packet.generate_packet() — regenerates session-resume.md, approval-gates.md, next-sprint.md, evidence-review.md, contradictions.md from fresh JSON
3. Added Step 7c: build_context_pack() — rebuilds .supervisor/context-pack.yaml and reports/supervisor/context-pack.md

## Declaration-First Principle
The canonical evidence unit is a **directory**, not a ZIP:
- Evidence root: `.local/evidences/<run_id>/`
- Declaration file: `evidence-declaration.yaml`
- Manifest file: `evidence-manifest.yaml`
- ZIP is optional (only for external transfer or archival)

Supervisor must support:
- Declaration-only + local materialization (primary path)
- Declaration review package (for external inspection)
- Legacy ZIP only as compatibility (deprecated)

## Impact
After this fix, running `autonomous_cycle.py --declaration <path>` produces a complete set of fresh outputs that any reader can consume without needing to know whether a ZIP was built.
