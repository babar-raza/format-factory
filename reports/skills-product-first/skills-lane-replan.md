## Q3: How does the governed source-change contract reduce false STOP signals?

The 5-tier enforcement model separates failure modes by severity:
- FAIL_CLOSED: product source changes (only Mainstream makes these)
- FAIL_WITH_REWORK: product tests/examples (Mainstream with Skills guidance)
- YES_WITH_LIMITATIONS: governance/tooling/templates (Skills autonomous)
- ACCEPT_WITH_LIMITATIONS: report-only planning (autonomous, advisory)
- BLOCKED_EXTERNAL_GATE: push/Gate 8/Gate 11 (true external gate, Stop)

Skills work is TIER 3 (YES_WITH_LIMITATIONS). A missing capability_matrix_update is a downgrade
(ACCEPT_WITH_LIMITATIONS), not a hard FAIL. This prevents false STOP signals for minor omissions.

## Q6: What happens if the MCP promotion fails or the registry update rolls back?

MCP promotion is not sprint-critical. If TC-W4-001 evaluates to KEEP_DEFERRED:
- TC-W4-002 closes as CLOSED_SKIPPED_WITH_REASON with documented reason.
- TC-W4-003 is skipped entirely.
- The sprint continues as KEEP_DEFERRED — still valid for SKILLS_PRODUCT_FIRST_GOVERNED_EXECUTION_PASS.
- A taskcard file documents the deferred state for the next sprint.

If the registry update fails validation (TC-W4-003):
- backup is immediately restored from skill-registry.before.yaml
- registry is revalidated (must pass)
- result.json records decision=ROLLED_BACK
- sprint continues as KEEP_DEFERRED

In both cases, the governance facilitation model classifies this as AUTONOMOUS_REWORK_REQUIRED or
GUARDED_AUTONOMOUS_ALLOWED — not HUMAN_OR_EXTERNAL_GATE_REQUIRED.

## Q7: How does the Skills lane hand off to the Supervisor for grading without losing evidence?

The supervisor grading integration works in three steps:
1. **Evidence declaration** (TC-W9-001): YAML work items per lane area with status, evidence_paths,
   and test_refs. All paths are absolute. No PENDING markers.
2. **Evidence manifest** (TC-W9-002): One entry per artifact with path + created_by_taskcard.
   >= 36 artifacts. All W10 entries included.
3. **Review package** (TC-W9-004): build_declaration_review_package.py bundles everything into
   a ZIP with SHA-256. The Supervisor inspects the ZIP to verify declared evidence exists.

The supervisor autonomous_cycle.py grades each work item against the evidence bundle.
If a work item is graded REJECTED or OVERCLAIMED, the sprint must rework before passing.
CLOSED_EXPECTED_FAILURE items are not sprint failures — they are pre-declared acceptable outcomes.
