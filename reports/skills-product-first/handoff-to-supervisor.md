## How Supervisor Grades Governed Source-Change Packets

The Supervisor autonomous_cycle.py grades each work item against the 5-tier contract.
The grading_rubric in `handoff-to-supervisor.json` specifies the exact grade for each tier.

## Grading Rules Summary

- **Tier 1 (FAIL_CLOSED):** All 9 MVP fields required. Missing any → REJECTED.
- **Tier 2 (FAIL_WITH_REWORK):** 8 fields required. Missing → FAILED_NEEDS_REPAIR.
- **Tier 3 (YES_WITH_LIMITATIONS):** 5 fields required. Missing optional → ACCEPTED_WITH_LIMITATIONS.
- **Tier 4 (ACCEPT_WITH_LIMITATIONS):** 3 fields required. Advisory — always ACCEPTED.
- **Tier 5 (BLOCKED_EXTERNAL_GATE):** Records blocker — BLOCKED_EXTERNAL.

## Anti-False-Positive Rules

- Missing capability_matrix_update on a Tier 1 item → DOWNGRADE to ACCEPT_WITH_LIMITATIONS (not REJECTED)
- Missing ledger_entry_id on a non-src-editing item → WARNING (not FAIL)
- Dry-run transcript with empty actual_files_changed → ACCEPTED (expected for mode=dry-run)
- CLOSED_EXPECTED_FAILURE fixtures → ACCEPTED (not counted as sprint failures)
