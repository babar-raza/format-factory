# Downstream Layer Audit — Format Factory Machinery Audit v2
# Sprint ID: ff-machinery-readiness-audit-v2-20260621-827f5a52

## Downstream Layer Overview

Downstream layers convert spec facts → capabilities → features → product code.

### Layer Stack

```
SAL (spec facts)
  ↓
Capability Layer (gap-ledger.json, capability maps)
  ↓
Feature Compiler (capability_compiler.py, product_feature_factory.py)
  ↓
Skills (add-python-api.md, add-dotnet-api.md, etc.)
  ↓
Product Source (src/python/, src/net/)
  ↓
Tests (tests/python/, tests/dotnet/)
  ↓
Exporters / Cross-format conversion
  ↓
Gate criteria (C1-C20, P1-P11)
  ↓
Gate 11 packet → Babar Raza
```

## Layer 1: SAL → Capability

Connection: MANUAL / STATIC
Evidence: Gap ledger generated by single run (sprint FORMAT-FACTORY-CAPABILITY-FEATURE-UNDERSTANDING-LAYER-INVESTIGATIVE-HEALING-001 on 2026-06-08)
- 625 of 958 gaps have spec_facts field (populated at creation time)
- Gaps do not dynamically pull from SAL at task selection time

What works: Gap ledger exists, has structure, some spec_facts populated
What doesn't: No live SAL query at sprint time; 333 gaps lack spec_facts

## Layer 2: Capability → Feature

Connection: capability_compiler.py EXISTS but reads wrong SAL path
Evidence: capability_compiler.py reads `.local/sal-output/sal-facts-latest.json`
- This path contains template facts from old pipeline
- Workbench facts are at `.local/spec-cache/sal-facts-fods.json`

What works: Compiler structure, gap record parsing, taskcard generation logic
What doesn't: Input path is wrong; compiler not wired into sprint selection loop

## Layer 3: Feature → Code (Skills)

Connection: Skills are prompt-based; gap-ledger.json read via `selected-product-gaps.json`
Evidence: `.local/supervisor/selected-product-gaps.json` — product gaps selected for sprint work

What works: Sprint loop selects gaps; skills generate code based on gap description
What doesn't: Skills don't enforce QName; generated code is not spec-literal; no capability_compiler.py integration

## Layer 4: Same-Format Save / Roundtrip

FODS Python: write_fods(wb, path) works — proven by test_r47_writer_hardening.py
FODS .NET: FodsDocument.Save(path) works — proven by Gate 11 criteria
FODT Python: write_fodt(doc, path) works
Other formats: Variable (some have writers, some don't)

## Layer 5: Cross-Format Export

FODS .NET: CSV, HTML, JSON, ODS exporters exist
FODS Python: csv_exporter.py exists
FODT .NET: HTML, Markdown, TXT exporters exist
FODT Python: Limited cross-format export

## Layer 6: Gate Logic

Gate checks are manual (/check-gate command).
Gate criteria C1-C20 and P1-P11 are defined in docs/commercial-gate11/.
No automated gate readiness scorer runs as part of each sprint.

## Key Downstream Gaps

1. Feature compiler not wired into sprint loop — code deepening is not compiler-driven
2. QName not propagated from SAL through all layers
3. Exporters are format-specific, not driven by a cross-format registry
4. Gate criteria check is manual, not automated per sprint
