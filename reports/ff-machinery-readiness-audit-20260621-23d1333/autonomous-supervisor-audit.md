## Lane Separation Assessment

### Current State: NO SEPARATE LANES

The autonomous supervisor has ONE continuation track ("product"). There is NO separate
"machinery" track for SAL repairs, qname implementation, backfill, or validator work.

Consequences:
1. Machinery sprints compete with product sprints in the same queue
2. A machinery sprint failure can block product continuation and vice versa
3. Lane contamination is possible: a product sprint that touches machinery files (e.g., adding a validator) cannot be separated from product deepening
4. There is no supervisor gate that says "machinery readiness confirmed, product lane may open"

### Required Separation

```
Track A — Machinery Lane
  - SAL pipeline repairs
  - QName canonical class creation
  - Backfill migration
  - Validator additions to governance_validators.py
  - Supervisor tooling improvements

Track B — Product Lane
  - Product feature implementation
  - Gate 11 readiness work
  - Export chain implementation
  - Dogfood proofs
```

These need separate continuation-signal files, separate evidence directories,
and separate check_continuation.py invocations.
