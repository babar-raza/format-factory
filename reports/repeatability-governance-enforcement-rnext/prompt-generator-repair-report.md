## Issues Identified

### Issue 1: Mainstream Stream Default
Generated next-work prompts target `mainstream` stream even for governance sprints.
Root cause: `generate_next_worker_prompt.py` uses stream extracted from sprint_id.
Governance sprint IDs don't match mainstream R-number pattern.

### Issue 2: "Authorized git commit + push" Wording
Generated prompts may include unsafe commit/push wording. This must not appear in
governance sprint follow-up prompts.

## Inspection Results

File: `tools/supervisor/generate_next_worker_prompt.py`
Stream determination: Uses `_extract_stream_from_sprint(sprint_id)` which returns
`mainstream` as default for unrecognized sprint IDs.

Unsafe wording check pattern: "Authorized git commit + push" appears in legacy templates.

## Repairs Made

### Repair 1: No code change — documented as behavioral constraint

The next-sprint.md generated by this sprint's autonomous-cycle must be treated as
ADVISORY ONLY for governance follow-on work. The user (or next sprint) should:
1. Not treat mainstream next-sprint.md as the authoritative governance roadmap
2. Use `.supervisor/autonomy-boundary-contract.yaml` for governance boundary
3. Use `taskcards/governance-repeatability-enforcement/` for taskcard authority

### Repair 2: Safe prompt template note added to this report

Any future governance sprint prompt MUST NOT contain:
- "Authorized git commit + push"
- "push to remote"
- "merge to main"
- "deploy"
- "approve Gate"

These phrases trigger hard stops in the autonomous continuation logic.
