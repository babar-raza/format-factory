## Mitigation Strategy

### Rule 1: Skills stream MUST generate its own state files

Skills primary state must live under `reports/skills-r105/`, not under `reports/supervisor/`.
The following files should be generated by the Skills pipeline:

| Skills-Primary File | Purpose |
|---------------------|---------|
| `reports/skills-r105/session-resume.md` | Skills-specific session resume |
| `reports/skills-r105/evidence-review.md` | Skills-specific evidence review |
| `reports/skills-r105/contradictions.md` | Skills-specific contradiction report |
| `reports/skills-r105/generated-next-skills-prompt.md` | Skills next sprint prompt |
| `reports/skills-r105/context-pack.yaml` | Skills-specific context pack snapshot |

### Rule 2: Global state labeled non-authoritative for Skills

Files under `reports/supervisor/` should be treated as **GLOBAL_CONTEXT** by Skills
workers, never as **SKILLS_PRIMARY**. Any Skills evidence package that includes
`reports/supervisor/` files must place them under a `global-state/` subdirectory and
label them as non-authoritative.

### Rule 3: Wrong-stream outputs not accepted as Skills evidence

Supervisor outputs generated by Mainstream or Acceleration runs must never be cited as
primary evidence for a Skills sprint. If referenced at all, they must be classified as
`WRONG_STREAM_PRIMARY` and excluded from Skills acceptance criteria.

### Rule 4: Skills next prompt at dedicated path

The Skills next sprint prompt must be generated at:
```
reports/skills-r105/generated-next-skills-prompt.md
```
Not at `reports/supervisor/next-sprint.md`, which is overwritten by the last stream
to run the supervisor pipeline.
