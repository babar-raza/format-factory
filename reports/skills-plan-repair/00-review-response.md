# Plan Review Response — v3.0 vs v5.0 Repair Assessment
Sprint: FORMAT-FACTORY-SKILLS-PRODUCT-FIRST-GOVERNED-EXECUTION-001
Generated by: TC-HEAL-001

## Overview

This document scores the v3.0 plan against all 10 required repair areas and explains how each
gap is addressed in v4.0/v5.0.

---

## Repair Area 1: Coordinator/Swarm Model

**v3.0 state:** No coordinator lane. Lanes executed without explicit integration order, overlap
detection, or file ownership mapping.

**Gap:** Two lanes could write the same file. No explicit integration sequencing.

**v5.0 fix:** Lane 0 (Coordinator) added as a mandatory first step. Outputs: file-ownership-map.json,
overlap-check.md, lane-ownership.md, coordinator-integration-log.md. Enforces integration order
(W0 → W1 → W2 → W3/W5/W7/W10 parallel → W4 → W6 → W8 → W9).

---

## Repair Area 2: Machine-Readable Taskcard State

**v3.0 state:** Taskcards existed only as markdown. No machine-parseable state tracking.

**Gap:** Autonomous grading could not verify taskcard closure status.

**v5.0 fix:** taskcard-state.json introduced (TC-W0-007). Schema: id, title, lane, owner, status,
dependencies, allowed_paths, forbidden_paths, evidence_paths, acceptance_check, closeout_status,
blocker_reason. 7 allowed status values. Acceptance check: python parse + length >= 43 entries.

---

## Repair Area 3: Registry Rollback Hardening

**v3.0 state:** Registry update was a single step. No backup, no rollback path if validation failed.

**Gap:** A failed registry edit could leave the registry in a broken state.

**v5.0 fix:** TC-W4-003 implements a 6-step atomic procedure: SHA-256 snapshot → backup copy →
edit → validate immediately → write result.json (PROMOTED or ROLLED_BACK) → if FAIL, restore
backup and revalidate. The sprint continues as KEEP_DEFERRED on rollback.

---

## Repair Area 4: MCP Optional (Not Sprint-Critical)

**v3.0 state:** MCP promotion was treated as a required step. Sprint could fail if promotion failed.

**Gap:** MCP promotion is governance infrastructure, not a product goal. It should not block a pass.

**v5.0 fix:** TC-W4-001 evaluates 10 criteria. If overall_decision = KEEP_DEFERRED, TC-W4-002
creates a deferred taskcard (CLOSED_SKIPPED_WITH_REASON) and TC-W4-003 is skipped. Sprint
passes with valid MCP taskcard and KEEP_DEFERRED decision.

---

## Repair Area 5: Expected-Failure Fixture Semantics

**v3.0 state:** All fixtures were expected to PASS. Failing fixtures were treated as sprint failures.

**Gap:** Receiver fixtures designed to test rejection must actually FAIL the validator. Treating
a fixture FAIL as a sprint failure is incorrect.

**v5.0 fix:** TC-W5-002 through TC-W5-009 are 8 explicitly failing fixtures. Expected result = FAIL.
Closure status = CLOSED_EXPECTED_FAILURE. TC-W5-011 captures all 10 results with match=true
(PASS for compliant, FAIL for failing). Unexpected PASS on a FAILING fixture triggers repair.

---

## Repair Area 6: Autonomous-Cycle Acceptance Tightened

**v3.0 state:** Autonomous cycle could pass with PENDING markers or OVERCLAIMED items.

**Gap:** Supervisor grading would still reject these items in a real sprint closeout.

**v5.0 fix:** TC-W9-003 acceptance criteria: exit 0, no REJECTED, no OVERCLAIMED, no PENDING.
Expected failures = CLOSED_EXPECTED_FAILURE (allowed). Recovery paths documented for exit 1
(fix YAML), exit 3 (repair evidence or downgrade claim).

---

## Repair Area 7: Review Package Wired In

**v3.0 state:** No build_declaration_review_package.py invocation. No SHA-256 or ZIP path in response.

**Gap:** Without the review package, the supervisor cannot inspect evidence bundles.

**v5.0 fix:** TC-W9-004 wires in the build command with --declaration and --out-dir. SHA-256
computed and stored in raw-logs/review-package-sha.txt. Final response contract requires absolute
path + SHA-256 + entry count.

---

## Repair Area 8: Per-Wave Rollback and Recovery

**v3.0 state:** No documented recovery paths. Agent would stop on local fixable failures.

**Gap:** Stops for locally-fixable issues waste sprint capacity.

**v5.0 fix:** Per-wave rollback/recovery table added to plan. 10 scenarios covered: missing artifact
(create it), invalid YAML (repair and rerun), transcript validation failure (fix fields and rerun),
adoption compliance failure (add missing reference and rerun), registry failure (restore backup),
unexpected fixture result (fix fixture), autonomous_cycle failure (fix declaration or downgrade claim),
external gate (stop and record blocker).

---

## Repair Area 9: Final Response Contract

**v3.0 state:** No specified format for the final response.

**Gap:** Without a contract, the supervisor cannot verify a complete response.

**v5.0 fix:** Final Response Contract section added to plan with all required fields: VERDICT,
Sprint ID, Changed Files Summary, Registry Promotion Decision, MCP Readiness Result, Test Command
and Result, Transcript Validation, Fixture Validation, Autonomous Cycle Exit Code, Evidence Declaration
and Manifest paths, Review Package absolute path + SHA-256 + entry count, Final Git Status,
Superpowers Evaluation Result, Install/No-Install Decision, and explicit notes (no push, no commit,
no plugin install, no Gate 8/11 approval).

---

## Repair Area 10: Self-Contained Execution Prompt

**v3.0 state:** Execution relied on external references. Not self-contained.

**Gap:** An agent receiving the prompt could not execute without reading other documents.

**v5.0 fix:** TC-HEAL-004 creates final-single-go-execution-prompt.md (> 5000 bytes) containing
all wave descriptions, all TC-* IDs, all acceptance checks, rollback/recovery table, final response
contract, and exact tool invocations. No external references needed.
