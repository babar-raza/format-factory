# 08 — First Divergence Point

**Baseline commit:** dd909cf3a

## The Divergence

**Starting state:** Identical committed repository at dd909cf3a. Two valid agents start from the same code.

**Agent A** follows CLAUDE.md instructions literally:
1. Reads session-resume.md → finds prior sprint context
2. Runs FF6 goal_driver resume → gets CONTINUE, 4/6 certified (false), next task for ORA/UBL
3. Starts working on ORA obligations

**Agent B** follows CLAUDE.md instructions literally:
1. Reads session-resume.md → finds prior sprint context
2. check_continuation.py returns STOP (NO_SIGNAL or SESSION_MISMATCH)
3. Supreme Directive overrides STOP → reads next-sprint.md directly
4. next-sprint.md may contain gen-1 deepening work or stale FF6 context
5. Starts working on whatever next-sprint.md says

**Agent C** follows the autonomous_task_generator path:
1. Runs autonomous_task_generator.py
2. lane_selector.py reads product-deepening-ledger.yaml
3. Returns format_not_found for all FF6 formats
4. Falls back to gen-1 expansion goals (ABW, DIF, FODG)
5. Starts working on ABW analytics expansion

## Why It Happens

The divergence occurs because:

1. **Multiple valid entry points exist** — CLAUDE.md says to run FF6 goal_driver resume AND check_continuation.py. Their outputs are not reconciled.
2. **Override rules create routing ambiguity** — when check_continuation returns STOP, Supreme Directive says "read next-sprint.md directly." But goal_driver may say CONTINUE for FF6 work. Which wins?
3. **Task selection is not unified** — next-sprint.md (generated by autonomous_cycle) and goal_driver (state-derived) may select different work.
4. **Generic deepening is not scoped** — lane_selector returns format_not_found for FF6 but this doesn't trigger FF6 routing.

## First Exact Code Location

The divergence begins at CLAUDE.md's "After Reading session-resume.md" section. Two independent checks run:
1. `python -m tools.ff6.goal_driver resume` → CONTINUE, work on ORA
2. `python tools/supervisor/check_continuation.py` → STOP/NO_SIGNAL → overridden → reads next-sprint.md → work on whatever's there

These are independent code paths with independent state sources. No mechanism reconciles their outputs.

## Impact

- Agent A works on ORA (correct for FF6 mission)
- Agent B works on stale next-sprint.md content (may be gen-1 or old FF6)
- Agent C works on ABW (gen-1, irrelevant to FF6 mission)

All three are "valid" under CLAUDE.md's rules. The text-based precedence rules try to prevent this but are not code-enforced.

## Resolution

R2 (authority decision) + R7 (single bootstrappable command) + R16 (consolidate continuation). One entry point, one state source, one task selection algorithm.
