# Source Hygiene Audit

**Sprint:** forensics-archaeology-20260621

---

## Summary

Source audits ARE polluted by build artifacts at multiple levels. However, the governance
tooling (source_structure_validator.py) correctly skips `build/` and `__pycache__` directories,
so they do not affect LOC or function counts for governance purposes. The visual noise and
disk pollution are real but functionally contained.

---

## Build Artifact Inventory

### Python egg-info (installed package metadata)

Committed or present at multiple levels:

| Path | Count | Issue |
|------|-------|-------|
| `src/python/format_factory_*.egg-info/` | 19 directories | Top-level (wrong location) |
| `src/python/{pkg}/format_factory_*.egg-info/` | 2 directories (abw, fods) | Package-level (expected) |
| `src/format_factory_dev.egg-info/` | 1 directory | Root-level |

**Root cause:** `pip install -e .` or `pip install --user` from the repo root or package roots
creates these. They should be in `.gitignore` but some appear to be committed to the working tree.

### Python `build/` directories (sdist/wheel artifacts)

| Package | Build Dir | Recursive? |
|---------|-----------|-----------|
| abw | `src/python/abw/build/` | No |
| dif | `src/python/dif/build/` | No |
| fods | `src/python/fods/build/` | YES — 3+ levels deep |
| fodt | `src/python/fodt/build/` | No |
| gnumeric | `src/python/gnumeric/build/` | No |
| ods | `src/python/ods/build/` | No |

**Recursive nesting worst case:** `src/python/fods/build/lib/fods/build/lib/fods/build/lib/fods/build/`
This happens when `python setup.py build` or similar is run from within the build directory.
The `fods/fods/` sub-package structure means the build system duplicates the package tree.

### .NET `bin/` and `obj/` directories

Present in all 10 .NET packages. These are standard .NET build outputs and should be in `.gitignore`.
Not a functional issue — MSBuild creates and manages them automatically.

## fods/fods/ Nested Package Issue

```
src/python/fods/
├── fods/              ← NESTED fods package (inside fods package)
│   └── spec/          ← spec stubs at nested level
└── spec/              ← spec stubs at top level
```

**Issue:** There are TWO spec directories:
1. `src/python/fods/spec/` — canonical, directly under the fods package (used by Compat/)
2. `src/python/fods/fods/spec/` — nested, appears to be an old structure

The `fods/fods/` directory contains `spec/spreadsheet/{cell,row,sheet,workbook}.py` which use
different class names (Cell, Row, Sheet, Workbook vs TableCell, TableRow, Table, Document).
These may represent an earlier attempt at spec stubs with different naming.

**Recommendation:** Audit `fods/fods/spec/` vs `fods/spec/` — determine which is canonical
and remove the duplicate.

---

## __pycache__ in Source

`__pycache__` directories exist inside `src/python/fods/spec/` subdirectories. These are
Python bytecode caches generated by running the code. Should be in `.gitignore`.

---

## Missing .gitignore Coverage

The following patterns should be in `.gitignore` but may be missing or insufficient:
- `*.egg-info/`
- `src/python/*/build/`
- `src/python/build/`
- `__pycache__/`
- `src/net/*/bin/`
- `src/net/*/obj/`

## Impact on Source Audits

| Audit Type | Impact |
|-----------|--------|
| `qname_structure_validator.py` | SKIPS build/ and __pycache__ — not affected |
| `source_structure_validator.py` | SKIPS build/ and nested duplicates — not affected |
| Manual file listing (ls/find) | Heavily polluted — can cause confusion |
| LOC measurement | Not affected (validator skips build/) |
| Class inventory | Not affected (validator skips build/) |
| Import resolution | May be affected if build/ adds stale .py files to path |

**Conclusion:** Governance tools are correctly protected. Human readability of the source
tree is significantly degraded. The `fods/fods/` duplication is the highest-risk artifact.
