## 12-State Artifact Lifecycle Applied to External Tool Outputs

External tool outputs enter the artifact lifecycle at `ai_draft` and may NOT advance
past `ai_draft` without evidence validation by the mainstream pipeline.

| State | External Tool May Produce? | Notes |
|-------|---------------------------|-------|
| 1. ai_draft | YES — required entry state | All external tool outputs must start here |
| 2. runtime_advisory | YES (Ruflo only) | Advisory signals; never evidence |
| 3. proposed | NO | Acceleration internal state only |
| 4. under_review | NO | Supervisor pipeline only |
| 5. review_blocked | NO | Supervisor pipeline only |
| 6. accepted_with_limitations | NO | Human reviewer only |
| 7. accepted | NO | Human reviewer only |
| 8. rejected | NO | Supervisor pipeline only |
| 9. deferred | NO | Human decision only |
| 10. authoritative_after_gate | NO | Gate approval only |
| 11. withdrawn | NO | Supervisor pipeline only |
| 12. archived | NO | Supervisor pipeline only |

**Rule:** External tools may not cause artifacts to advance in the lifecycle.
Only the evidence pipeline (tests + validator + human gate) may advance artifacts.

## Invariants (enforced throughout sprint)

1. No external tool output carries `authority_state` other than `ai_draft` or `runtime_advisory`
2. No external tool writes to authority files (poc-targets.yaml, skill-registry.yaml, plans/master-plan.md)
3. No external tool is installed or activated during this sprint without explicit evidence
4. All Mainstream consumption packets work without any external tool installed
5. External tool context fields in packets always have `external_tool_activation_required_for_packet: false`
