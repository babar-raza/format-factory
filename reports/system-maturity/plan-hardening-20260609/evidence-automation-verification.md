## TC-E3: Lane Execution Ledger Requirement

### Current State
- File: `.local/supervisor/lane-execution-ledger.json`
- Content: 1 entry only (ACCEL-R99-TEST, 43 tests pass)
- Assessment: PROOF-OF-CONCEPT. Most sprints did not write lane entries.

### Required Ledger Fields (per entry)
```yaml
lane_id: string (unique per execution lane)
sprint_id: string (sprint this lane belongs to)
concurrency_group: string (parallel execution group)
owner: string (agent/role responsible)
started_at: ISO 8601 timestamp
ended_at: ISO 8601 timestamp
files_read: [file paths]
files_changed: [file paths]
commands: [commands executed]
tests_run: [test commands]
test_count: integer
tests_passed: integer
tests_failed: integer
status: completed | failed | aborted
blockers: [descriptions]
notes: string
```

### Requirement
Every taskcard that reaches IN_PROGRESS must write a lane-execution-ledger entry upon transition to IMPLEMENTED. This provides:
1. Audit trail for what each taskcard actually did
2. Input for evidence_auto_packager to derive work items
3. Anti-skip evidence for raw log detection (detector #3)
4. Replay basis for idempotency proof

## TC-E4: ACCEPTED_VERIFIED Path-Only Evidence Blocker

### Problem
Historical evidence reviews have granted ACCEPTED_VERIFIED to work items whose evidence consisted only of file paths without actual content proof (test logs, sample outputs, or command results).

### Proposed Rule
**ACCEPTED_VERIFIED requires at least one non-path evidence artifact:**
- Raw test log (pytest output or equivalent)
- Sample output file (generated by the code being tested)
- Command output (shell command result proving functionality)

**Path-only evidence may receive at most:** ACCEPTED_WITH_LIMITATIONS

### Implementation Point
In grade_declared_work.py, before assigning ACCEPTED_VERIFIED:
1. Check evidence_paths for at least one file with content (not empty)
2. Check for presence of test log file (*.log or test output capture)
3. If only file paths present and no content evidence → downgrade to ACCEPTED_WITH_LIMITATIONS

## TC-E5: Anti-Skip Raw Logs and Sample Outputs Review

### Detector #3: Missing Raw Logs
- **Purpose:** Flag evidence without test logs
- **Severity:** medium
- **Current behavior:** Checks for test log files in evidence_root
- **Assessment:** FUNCTIONAL — fires correctly when logs are missing
- **Gap:** Does not verify log content (could accept empty log files)

### Detector #9: Missing Sample Outputs
- **Purpose:** Flag evidence without sample output files
- **Severity:** medium
- **Current behavior:** Checks for sample output files in evidence_root or declaration paths
- **Assessment:** FUNCTIONAL with known caveat — uses glob discovery which may miss files in non-standard locations
- **Gap:** Does not verify sample output content quality (could accept trivial outputs)

### Recommended Improvements
1. Detector #3: Add minimum log file size check (>100 bytes) to prevent empty logs
2. Detector #9: Add content verification (output file must contain format-specific data, not just empty/boilerplate)
3. Both: Promote severity to "high" for PRODUCT_SOURCE items to prevent overclaiming
