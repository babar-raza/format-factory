## Finding Summary

The action queue is empty. This is NOT a wiring bug. The root cause is that all
open gap-ledger entries have `suggested_taskcard: ""` (empty string), causing
`_build_action_queue()` to skip every gap.

---

## Two Separate Queue Systems (Clarification)

The plan referenced `.local/rcal/action-queue.json` — this path does NOT exist.
The actual action queue infrastructure uses two separate files:

| Queue | Path | Purpose | Status |
|-------|------|---------|--------|
| Capability-layer advisory | `reports/capability-layer/action-queue.json` | Advisory; read by sprint selector | **0 actions** |
| Orchestrator DURABLE | `.local/supervisor/action-queue.jsonl` | JSONL queue for autonomous orchestrator | 53 items (all `status: done`) |

## Root Cause

### File: `tools/capability_layer/capability_map_generator.py` `_build_action_queue()` lines 986-1020

```python
for gap in gaps[:20]:  # top 20 gaps
    if not gap.get("suggested_taskcard"):
        continue  # <-- SKIPS all gaps without a suggested_taskcard
    ...
```

**The skip condition fires for every gap**: All 61 open gaps and all 20 top gaps have
`suggested_taskcard: ""` (empty string), so the `if not gap.get(...)` check is True
for all of them. The loop appends 0 actions.

### Evidence

```

  with suggested_taskcard: 0
  without suggested_taskcard: 20
All open gaps: 61
Open gaps with suggested_taskcard: 0
```

## Gap-Ledger Quality Analysis

The gap-ledger has `total_gaps: 891` with `61` open entries. Closed gaps
(closed during various sprints) account for 830. The 61 open gaps come from
recent capability-layer healing sprints and lack populated `suggested_taskcard` values.

Gap-ledger generation is in `tools/capability_layer/capability_map_generator.py`.
The `suggested_taskcard` field is populated via:
```python
"suggested_taskcard": gap.get("suggested_taskcard", "")
```
...i.e., it's passed through from whatever the input data provides.
Since the input POC targets and capability maps don't embed suggested taskcards,
the field stays empty.

## Permanent Solution (Architectural)

Two options:

### Option A (Preferred): Populate suggested_taskcard from skill registry
When `_build_action_queue` processes a gap, auto-derive a suggested taskcard
from the gap's `gap_type` and `format`. Example mapping:
- `missing_test_coverage` → `TC-TEST-{FORMAT}-{CAP_NAME}-001`
- `spec_qname_not_activated` → `TC-QNAME-{FORMAT}-001`
- `missing_implementation` → `TC-IMPL-{FORMAT}-{CAP_NAME}-001`

This requires modifying `_build_action_queue` to generate the taskcard ID
when `suggested_taskcard` is empty.

### Option B: Remove the skip condition
Change `if not gap.get("suggested_taskcard"): continue` to generate actions
for ALL gaps, marking them advisory even when no taskcard is pre-specified.
