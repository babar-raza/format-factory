# [Draft, not submitted] GEGL: `svg:overlay`/`svg:hard-light`/`gegl:soft-light` premultiplied formula does not match the W3C spec

**Project**: GEGL (GNOME/gegl)
**Version**: 1:0.4.48-2.4build2 (Ubuntu 24.04 `apt` package)
**Component**: `operations/generated/overlay.c`, `operations/generated/
hard-light.c`, `operations/generated/soft-light.c` (all generated by
`svg-12-blend.rb`)
**Severity**: Correctness — these 3 blend operations produce values that
diverge from the W3C Compositing and Blending Level 1 spec these files'
own header comments cite

## Reproduction

```
gegl <dest.png> -o <result.png> -- svg:overlay srgb=true aux=[load path=<src.png>]
```

Minimal counter-example not tied to any project-specific fixture (both
layers fully opaque, so the general compositing formula collapses to
the blend function alone): `Cb=0.3, Cs=0.3` (RGB, all channels equal) →
expected `Multiply(Cs, 2×Cb) = 0.18`; a second, asymmetric case
`Cb=0.2, Cs=0.9` → expected `Multiply(Cs, 2×Cb) = 0.36`. Full
project-fixture-based reproduction (backdrop=(30,200,60) opaque,
source=(220,40,180) alpha=166/255) committed at
`tools/ora/producer_harness/gegl/evidence-2026-08-12b/`.

## Expected result

Per the W3C Compositing and Blending Level 1 spec, section 10
(`https://www.w3.org/TR/compositing-1/#blending`), the normative
combined premultiplied formula is:

```
αo × Co = αs × (1-αb) × Cs + αs × αb × B(Cb,Cs) + (1-αs) × αb × Cb
```

For the two fully-opaque counter-examples above (`αs=αb=1`), this
reduces to `Co = B(Cb,Cs)` exactly, i.e. `Multiply(Cs, 2×Cb)` in the
`Cb≤0.5` branch of Overlay/Hard-Light. Expected values: `0.18` and
`0.36` respectively.

## Actual result

`operations/generated/overlay.c`'s own ELSE-branch (`Cb≤0.5`) formula —

```c
out[j] = CLAMP (aA * aB - 2 * (aB - cB) * (aA - cA) + cA * (1 - aB) + cB * (1 - aA), 0, aD);
```

— evaluated by direct substitution at `aA=aB=1, cA=cB=0.3` (fully
opaque, so premultiplied = straight) gives `0.02`, not `0.18`. At
`aA=aB=1, cA=0.9, cB=0.2` gives `0.84`, not `0.36`. `hard-light.c`
shares the identical formula (structurally, condition inverted per
Hard-Light's own definition). `soft-light.c` (registered as
`gegl:soft-light`, not `svg:soft-light`, despite the identical
generator/spec citation) shows the same defect class, spot-checked at
`Cb=0.1, Cs=0.2` (fully opaque): expected `0.046`, actual `0.154`.

## Root cause

Algebraic: hand-expanding GEGL's own ELSE-branch formula symbolically
does not reduce to the W3C spec's own normative formula for the
`Cb≤0.5` sub-case (`B = Multiply(Cs, 2Cb) = 2CsCb` in premultiplied
terms `2×cA×cB`) — the generated formula's own cross-terms
(`aB*cA`, `aA*cB`, sign of the `cA*cB` term) do not match. This
appears to be an error introduced by the `svg-12-blend.rb` generator
script's own premultiplied-reformulation algebra for this specific
piecewise (2-or-3-branch) family of blend functions, not present in
the simpler, single-formula Porter-Duff family (`plus.c`, `dst-atop.c`,
etc., all independently confirmed CORRECT against format-factory in
this same investigation).
